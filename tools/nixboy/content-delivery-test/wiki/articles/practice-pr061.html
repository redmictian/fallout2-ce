Starting contract

Complete L-PR-C/memory-model first. The assigned Linux terminal supplies two current Python 3 processes, not a programming task. Both hold a 256 MiB private anonymous mapping and wait without a timed exit while this assignment remains open. One has not touched the mapping. The other wrote every byte of its first 16 MiB and then discarded its temporary writing buffer. Neither mapping is locked or prefaulted. Their command lines are inspectable. PIDs are deliberately discovered each attempt.

The observation system has at least 1 GiB usable RAM, no active pressure workload, and exposes coherent system-scope proc counters. Exact current mount capacity, kernel/tool editions and live PIDs are supplied in the practice handout; no fixed PID or RAM value is an answer. All initial file mtimes are 2026-01-15T12:00:00Z. Tools: Bash, Python 3, GNU coreutils/grep, procps ps/vmstat, util-linux findmnt, getconf, less and installed help. No privilege change is needed.

1 · Predict before measuring

Both processes map 256 MiB. Must both report approximately 256 MiB RSS? Does a p permission letter prove every page in that range is resident and uniquely owned?

Feedback

No to both. The mappings reserve virtual ranges. The touched process needs backing for the region it wrote; the untouched range need not be resident. A private mapping describes write semantics; it does not itself give resident-page accounting or rule out initially shared clean pages elsewhere.

2 · Identify the two current views

$ a=$(cat /srv/pr061-practice/targets/untouched.pid)
$ b=$(cat /srv/pr061-practice/targets/touched.pid)
$ ps -p "$a,$b" -o pid,user,etimes,pcpu,vsz,rss,args
$ cat /proc/"$a"/maps
$ cat /proc/"$a"/smaps_rollup
$ cat /proc/"$b"/smaps_rollup
$ less /proc/"$a"/smaps
$ less /proc/"$b"/smaps

Find each approximately 262144 KiB anonymous range; address-space layout randomization changes its address. Save the mapping header and its Size/Rss/Pss/Private_Dirty/Swap fields. Compare this mapping, then compare process totals. Do not demand that a process total equal its one selected mapping.

Compare your result

Both ranges should have size 256 MiB. The untouched selected range should have little or no residency. The touched selected range should have about 16 MiB resident private dirty memory, subject to declared page policy and movement during observation. Process totals include the Python interpreter, shared libraries, stack and other mappings. The temporary byte buffer can affect process totals even after it is no longer a live Python object. That is a reason to inspect the selected mapping, not an unexplained failure of the virtual-memory model.

If the selected range was merged or the expected state is absent, save the evidence and report it. The specification expects the reference commands below to be preflighted on the supplied software; do not invent missing output.

3 · Put snapshots beside an interval

$ vmstat -w -y 1 5
$ grep -E '^(MemTotal|MemFree|MemAvailable|Cached|SwapTotal|SwapFree):' /proc/meminfo
$ grep -E '^(pgfault|pgmajfault|pgscan_kswapd|pgscan_direct|pgsteal_kswapd|pgsteal_direct|pswpin|pswpout) ' /proc/vmstat
$ sleep 10
$ grep -E '^(pgfault|pgmajfault|pgscan_kswapd|pgscan_direct|pgsteal_kswapd|pgsteal_direct|pswpin|pswpout) ' /proc/vmstat

Record the two times and at least one counter delta. Predict why the fault delta need not equal the number of pages touched by the second process.

Feedback

The writing happened before this observation interval. These are also system counters: your commands and other tasks contribute. A nonzero fault count during the interval does not prove the sleeping process touched its range again or caused pressure. The healthy starting contract does not promise every counter stays exactly zero.

4 · Match the storage report to the actual path

$ findmnt -T /srv/pr061-practice/volume/data/seed.txt
$ df -B1 /srv/pr061-practice/volume
$ df -i /srv/pr061-practice/volume

Save the mount identity, available bytes and free inodes. Record why free bytes alone would not guarantee another file could be created.

Feedback and completion check

A new object can also need a free inode and correct access rights. The practice volume has both kinds of capacity, but that fact comes from the measured path and its declared filesystem. You have finished when you have the correct two identities; the selected mapping comparison; system CPU and memory observations; a timed counter delta; and byte/inode observations for the right volume, with protected state unchanged.

Use a compact table: observation → scope → unit/interval → value → warranted conclusion. No essay assessment is attached to this practice. If the large range has small RSS, your conclusion is “much of this view is not resident now,” not “this process can never need memory.”

Supplied stimulus, for a transparent practice

The following are the complete reference invocations used to prepare the two observations. They use Python's existing Unix mmap interface; learners do not implement or maintain an application. They are shown for explanation. The operator supplies the running processes and PID files before practice, rather than asking you to launch competing duplicates.

python3 -c 'import mmap,signal; m=mmap.mmap(-1,256*1024**2,flags=mmap.MAP_PRIVATE|mmap.MAP_ANONYMOUS); signal.pause()'
python3 -c 'import mmap,signal; m=mmap.mmap(-1,256*1024**2,flags=mmap.MAP_PRIVATE|mmap.MAP_ANONYMOUS); m[:16*1024**2]=b"x"*(16*1024**2); signal.pause()'
