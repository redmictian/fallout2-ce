# Delivery integration catalog

This optional catalog is a bounded infrastructure demonstration, not SA67 or a
finished course. It uses a fixed native nginx guest with two real client origins.

1. `delivery.nginx.1` starts with a deliberately open staff policy. Restore the
   declared source restriction, validate/reload nginx and record `X reload`.
2. Completion removes that guest. `delivery.nginx.2` starts from a separately
   prepared canonical stage-one contract with a new endpoint fault. Repair it,
   record a genuine reload, commit the bounded question and submit.

F7 before commitment restores the current canonical stage; previous completion
is retained. After conceptual commitment T creates an explicit new reassessment.
The default current profile uses no learner snapshots or carried files.

Stage two has one explicitly test-only reward: owned inert Toughness12/rank1 →
rank2. Prepare a disposable character with `--debug-perk=12:1`, close the review
screen, and open Ctrl+N → C. It never grants ownership or decides a permanent
educational mapping. Its separate legacy Science62000/+1 copy task is regression
content; it is not a course reward or a permanent mapping either.

service observations; [COURSE.md](../COURSE.md) owns stage/schema/retry contracts;
[PERK_REWARDS.md](../PERK_REWARDS.md) owns the explicit wire/save compatibility.
