A shell pipeline connects one command's standard output to the next command's standard input. Build it in stages so you can inspect what each command produces.

From records to a count

This example supplies three records, selects the two beginning with ERROR , then counts those lines:

printf 'INFO ready\nERROR relay\nERROR valve\n' | grep '^ERROR ' | wc -l
StageRole
printfProduce the example records
grep '^ERROR 'Keep lines with that prefix; ^ anchors the match at the start
wc -lCount newline characters in the selected output

First run only the producer. Then add the filter, inspect its output, and add the count last. This makes a wrong pattern easier to spot.

Save the output

> redirects standard output to a file, replacing its previous contents. >> appends. Create the directory from the paths lesson before trying this example:

printf 'INFO ready\nERROR relay\nERROR valve\n' | grep '^ERROR ' > ~/wiki-demo/errors.txt
cat ~/wiki-demo/errors.txt

The ordinary | operator carries standard output. Diagnostic messages on standard error do not automatically become input for the next stage.

Choose what the task actually needs

Extract failed service events needs the matching records themselves. A counter would discard that text. Read the requested final output before choosing your last stage.

If writing fails, inspect the destination path and its access permissions.
